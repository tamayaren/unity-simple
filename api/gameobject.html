GameObject

A GameObject is any object in your scene. On its own it's an empty container with a name and a Transform. You make it do things by adding components.

Inside a MonoBehaviour, gameObject (lowercase) is the GameObject the script is attached to. GameObject (uppercase) is the class, used for static functions like GameObject.Find.

Properties

SetActive(false) is unplugging an appliance. It's still in the room (in the Hierarchy), keeps its settings, and you can plug it back in anytime. Unplugging a power strip (a parent) turns off everything plugged into it (the children), even if each device's own switch (activeSelf) is still on.

NameTypeDescription
namestringName shown in the Hierarchy.
transformTransformIts position, rotation and scale. Every GameObject has one.
activeSelfboolIs this object's own checkbox ticked? (Read only. Use SetActive to change.)
activeInHierarchyboolIs it actually active? False if it or any parent is inactive.
tagstringA label like "Player" or "Enemy". Add tags in the Tags & Layers settings.
layerintLayer number (0-31). Used for physics filtering and camera culling.
sceneSceneThe scene it belongs to.

Code Samples

Getting components safely

using UnityEngine;

public class Damager : MonoBehaviour
{
    void OnTriggerEnter(Collider other)
    {
        // Does the thing we hit have a Health script?
        if (other.TryGetComponent<Health>(out Health health))
        {
            health.TakeDamage(10);
        }
    }
}

Showing and hiding a menu

using UnityEngine;

public class PauseMenu : MonoBehaviour
{
    [SerializeField] private GameObject menuPanel; // drag the menu UI object here

    void Update()
    {
        if (Input.GetKeyDown(KeyCode.Escape))
        {
            bool show = !menuPanel.activeSelf;
            menuPanel.SetActive(show);
            Time.timeScale = show ? 0f : 1f; // freeze the game while the menu is open
        }
    }
}

Building an object entirely from code

GameObject go = new GameObject("Enemy");  // an empty GameObject with only a Transform
go.transform.position = new Vector3(0f, 1f, 5f);
go.AddComponent<Rigidbody>();
go.AddComponent<BoxCollider>();
go.tag = "Enemy"; // the tag must already exist in Tags & Layers

What happens at runtime

SetActive(false)

  1. OnDisable is called on every script on the object and on all its children.
  2. The object stops rendering, its colliders are removed from physics, and Update / FixedUpdate stop being called.
  3. Coroutines running on its scripts are stopped (and won't resume when reactivated).
  4. Children keep their own activeSelf value, but their activeInHierarchy becomes false.

SetActive(true)

  1. OnEnable is called on enabled scripts. If a script's Awake has never run (object started inactive), it runs now, followed later by Start.

Common Mistakes

  • GameObject.Find can't find inactive objects. Keep a reference in a serialized field instead.
  • Calling Find or GetComponent every frame. Cache the result in Awake or Start.
  • Comparing tags with ==. Works, but CompareTag is faster and doesn't allocate memory.
  • Checking activeSelf when you mean "is it visible". A child can be activeSelf == true but hidden because its parent is off. Use activeInHierarchy.
