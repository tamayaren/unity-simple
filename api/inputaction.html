InputAction

An InputAction is a named thing the player can do, like "Move", "Jump" or "Fire", in the new Input System. Keys and buttons (bindings) are attached to it. Your code reads the action and doesn't care which device triggered it.

A restaurant order. Your code is the kitchen: it only needs to hear "one Jump, please". Whether the order came from the counter (keyboard), the drive-through (gamepad) or an app (touchscreen) is the waiter's job. The bindings are the waiters. Add a new waiter (a new device binding) and the kitchen code doesn't change at all.

EventFires when
startedInput began (button went down, stick left the center).

All three pass an InputAction.CallbackContext. Use ctx.ReadValue<T>() to get the value.

Code Samples

Polling (read every frame)

using UnityEngine;
using UnityEngine.InputSystem;

public class PollingPlayer : MonoBehaviour
{
    private InputAction move;
    private InputAction jump;

    void Awake()
    {
        move = InputSystem.actions.FindAction("Move");
        jump = InputSystem.actions.FindAction("Jump");
    }

    void Update()
    {
        Vector2 input = move.ReadValue<Vector2>();
        transform.position += new Vector3(input.x, 0f, input.y) * 5f * Time.deltaTime;

        if (jump.WasPressedThisFrame()) Debug.Log("Jump");
    }
}

Callbacks (react to events)

using UnityEngine;
using UnityEngine.InputSystem;

public class CallbackPlayer : MonoBehaviour
{
    [SerializeField] private InputActionReference fireAction; // pick the action in the Inspector

    void OnEnable()
    {
        fireAction.action.performed += OnFire;
        fireAction.action.Enable();
    }

    void OnDisable()
    {
        fireAction.action.performed -= OnFire;
    }

    private void OnFire(InputAction.CallbackContext ctx)
    {
        Debug.Log("Fire!");
    }
}

What happens at runtime

  1. Devices send events (key down, stick moved) to the Input System as they happen.
  2. By default, just before each frame's Update, the Input System processes those events and checks which bindings they match.
  3. Matching actions change phase (Waiting → Started → Performed → Canceled) and fire the corresponding C# events.
  4. The values you poll with ReadValue and WasPressedThisFrame reflect this processed state for the whole frame.

Common Mistakes

  • Action never fires. It isn't enabled. Call Enable() (or its map/asset's Enable()).
  • FindAction returns null. The name doesn't match, or you're using InputSystem.actions without a project-wide asset set in Project Settings > Input System Package.
  • Subscribing without unsubscribing. After the object is destroyed, the callback still runs and throws MissingReferenceException. Always -= in OnDisable.
  • Movement "sticks" after releasing keys when using only performed. Also handle canceled (which gives zero), or just poll with ReadValue.
