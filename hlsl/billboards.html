Camera-facing Billboards

Make a flat picture turn toward the camera, like the enemies, trees or labels used in many games.

Imagine someone holding a cardboard sign and turning it as you walk around, so you can always read the front. A billboard does the same thing for a flat picture in your game.

Start here

Start with the SpriteRenderer script. It is the easiest way to see the effect. The shader version is an optional next step after Your First HLSL Shader.

A few words first

A sprite is a 2D image used in a scene. A billboard is a flat image that turns toward the camera. A quad is a flat rectangle made from two triangles. An orthographic camera shows objects without making distant ones look smaller.

Choose what “faces the camera” means

StyleBehaviorUseful for
Screen-alignedAll billboards share the camera rotation; parallel even at the edge of the screen.Icons, floating labels, orthographic games.
Point-facingEach billboard aims at the camera position.Perspective objects spread across a wide view.
Cylindrical / Y-onlyRotate around world Y while staying upright.Trees and upright character cutouts.

1. A SpriteRenderer billboard

Import an image as Sprite (2D and UI), drag it into the scene, and attach this script. Assign the gameplay camera. Use a sprite material supported by your render pipeline. Use a normal upright sprite: its width follows local X and its height follows local Y. Let this script control its rotation; another script or animation changing it could make it flicker.

using UnityEngine;

public class SpriteBillboard : MonoBehaviour
{
    [SerializeField] private Camera viewCamera;
    [SerializeField] private bool keepUpright;

    void Awake()
    {
        if (viewCamera == null) viewCamera = Camera.main;
    }

    void LateUpdate()
    {
        if (viewCamera == null) return;
        if (!keepUpright)
        {
            // Screen-aligned: copy camera axes, including roll.
            transform.rotation = viewCamera.transform.rotation;
            return;
        }
        // Make local -Z face the camera while local Y stays vertical.
        Vector3 forward = transform.position - viewCamera.transform.position;
        forward.y = 0;
        if (forward.sqrMagnitude > 0.0001f)
            transform.rotation = Quaternion.LookRotation(forward, Vector3.up);
    }
}

LateUpdate usually runs after ordinary movement. If a camera rig also updates in LateUpdate, explicitly order this script after the rig if you see a one-frame lag. For point-facing behavior with tilt, remove the Y flattening from the upright branch. A camera directly above the sprite gives no horizontal direction; keeping the last rotation avoids an unstable LookRotation call.

For an orthographic camera, a Y-only screen-aligned billboard can instead flatten the camera's forward vector. Imported geometry may face local +Z rather than -Z; rotate its visual child 180 degrees if it appears backward. Do not use negative scale as the first fix because that also mirrors art and changes winding.

Going further: 2. A GPU billboard for a quad

The shader below uses the camera's right and up vectors to rebuild a quad around its world center. It is for a centred unit Quad with a MeshRenderer, not a SpriteRenderer: sprite atlases, vertex colors, sprite flips and 2D lighting are not implemented. It targets URP 17's Universal Renderer and a conventional non-XR camera.

  1. Create Billboard.shader with this code and a material using Simple/Billboard.
  2. Import a full-image RGBA texture (not an atlas region), assign it to Base Map, and use a Quad at unit scale.
  3. Assign the material to the Quad and orbit the camera. The image should retain the camera's orientation.
  4. Disable static batching on billboard objects. The shader needs each object's original center and local coordinates.
Shader "Simple/Billboard"
{
    Properties
    {
        _BaseMap ("Base Map", 2D) = "white" {}
        _BaseColor ("Tint", Color) = (1, 1, 1, 1)
        _Cutoff ("Alpha Cutoff", Range(0,1)) = 0.5
    }
    SubShader
    {
        Tags { "RenderPipeline"="UniversalPipeline" "Queue"="AlphaTest"
               "RenderType"="TransparentCutout" "DisableBatching"="True" }
        Pass
        {
            Tags { "LightMode"="SRPDefaultUnlit" }
            Cull Off
            ZWrite On
            HLSLPROGRAM
            #pragma vertex Vert
            #pragma fragment Frag
            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"
            struct Attributes { float4 positionOS : POSITION; float2 uv : TEXCOORD0; };
            struct Varyings { float4 positionHCS : SV_POSITION; float2 uv : TEXCOORD0; };
            TEXTURE2D(_BaseMap);
            SAMPLER(sampler_BaseMap);
            CBUFFER_START(UnityPerMaterial)
                float4 _BaseMap_ST;
                half4 _BaseColor;
                half _Cutoff;
            CBUFFER_END

            Varyings Vert(Attributes input)
            {
                Varyings output;
                float3 center = TransformObjectToWorld(float3(0,0,0));
                float3 right = UNITY_MATRIX_I_V._m00_m10_m20;
                float3 up = UNITY_MATRIX_I_V._m01_m11_m21;
                float width = length(TransformObjectToWorldDir(float3(1,0,0), false));
                float height = length(TransformObjectToWorldDir(float3(0,1,0), false));
                float3 world = center + right * input.positionOS.x * width
                                      + up * input.positionOS.y * height;
                output.positionHCS = TransformWorldToHClip(world);
                output.uv = TRANSFORM_TEX(input.uv, _BaseMap);
                return output;
            }
            half4 Frag(Varyings input) : SV_Target
            {
                half4 color = SAMPLE_TEXTURE2D(_BaseMap, sampler_BaseMap, input.uv) * _BaseColor;
                clip(color.a - _Cutoff);
                return half4(color.rgb, 1);
            }
            ENDHLSL
        }
    }
}

Bounds: the CPU cannot see the turn

Unity first checks whether an object might be visible, a step called culling. The shader turns its corners afterward. A flat quad's original bounds may be rejected even when its turned image should be visible. For this centred unit quad with uniform scale, attach this helper to give the renderer a conservative local cube. For non-uniform scale, shear, off-centre geometry, or additional displacement, calculate bounds large enough for those cases instead.

using UnityEngine;

[RequireComponent(typeof(MeshRenderer))]
public class BillboardBounds : MonoBehaviour
{
    void OnEnable()
    {
        // Unit quad corner radius is sqrt(0.5^2 + 0.5^2) ~= 0.707.
        GetComponent<MeshRenderer>().localBounds = new Bounds(Vector3.zero, Vector3.one * 1.5f);
    }
    void OnDisable() { GetComponent<MeshRenderer>().ResetLocalBounds(); }
}

Hard edges versus soft transparency

This shader discards low-alpha fragments and writes depth, which works well for crisp foliage and pixel-art cutouts. For soft edges, change Queue to Transparent and RenderType to Transparent, use Blend SrcAlpha OneMinusSrcAlpha and ZWrite Off, remove clip, and return the sampled alpha. Transparent objects are generally sorted by object rather than each pixel, so overlapping quads can show sorting artifacts and create heavy overdraw.

Multiple cameras and other limits

The C# version rotates the actual Transform for one camera, including child colliders. Split-screen cameras can disagree about its facing. The shader evaluates camera axes per view, but collision geometry stays in its original orientation. It has no shadow, depth-only or motion-vector passes; adding those requires matching the vertex deformation and deciding how a billboard should face during shadow rendering. This tutorial does not implement GPU instancing or stereo macros.

What happens at runtime

  1. The C# approach updates a real Transform after movement.
  2. The shader approach leaves the Transform alone and rebuilds visible vertex positions in the current camera's basis.
  3. Texture UVs stay attached to their corners; alpha clipping removes the background.

Common Mistakes

  • Calling LookAt without checking which local side of the image faces forward.
  • Expecting a GPU billboard to rotate its collider.
  • Using ordinary flat bounds after shader rotation.
  • Expecting a mesh shader to automatically handle packed SpriteAtlas UVs.
  • Turning on static batching and losing per-object origins.

Try it

Orbit a perspective camera, switch it to orthographic, and view the billboard from directly above. Test two cameras at once and move the quad to the screen edge. Those checks expose facing and bounds mistakes that a fixed front view hides.
