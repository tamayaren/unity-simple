Your First HLSL Shader

Write your first shader: put a texture on a shape, give it a color tint, and learn what each part of the code does.

Think of decorating a paper model. The vertex function places its corners. The fragment function chooses the colors on its surface. The material is your box of chosen paint and pictures; the shader is the set of instructions for using them.

Start here

Use a Universal 3D project, copy the complete shader, and get a textured Cube on screen. Then change the tint and try the UV color test. You do not need to memorize every keyword first.

A few words first

A shader is a small program used to draw things. HLSL is the language used for that program. It runs on the GPU, the part of your computer that draws graphics. ShaderLab is Unity’s wrapper around the HLSL code: it lists material settings and drawing rules.

Target: Unity 6, URP 17, Universal Renderer

These examples are for mesh rendering with URP's Universal Renderer. They are not Built-in Surface Shaders, HDRP shaders or Sprite-Lit shaders for the 2D Renderer. Start with a Universal 3D project; see the URP guide for pipeline setup.

Shader, material and renderer

A shader defines the GPU program and rendering rules. A material stores chosen values, such as texture and tint. A renderer supplies geometry and transforms. Ten materials can use the same shader with different values. A shader runs on many vertices and fragments in parallel; it is not a C# script with one Update call.

1. Create the assets

  1. Create a file named SimpleTexture.shader inside Assets. Replace its contents with the complete shader below.
  2. Wait for compilation, then create a Material and choose Simple/Texture from its Shader menu.
  3. Assign a texture to Base Map and choose a tint. Assign the material to a Quad or Cube.
  4. Point the camera at the mesh. The texture should remain visible even without a light because this shader is unlit.

Read this as three small jobs: Properties adds controls to the material, Vert places the corners, and Frag colors the surface. The rest connects those jobs to Unity.

2. The complete shader

Shader "Simple/Texture"
{
    Properties
    {
        _BaseMap ("Base Map", 2D) = "white" {}
        _BaseColor ("Tint", Color) = (1, 1, 1, 1)
    }
    SubShader
    {
        Tags { "RenderType"="Opaque" "RenderPipeline"="UniversalPipeline" }
        Pass
        {
            Name "Unlit"
            Tags { "LightMode"="SRPDefaultUnlit" }
            HLSLPROGRAM
            #pragma vertex Vert
            #pragma fragment Frag
            #include "Packages/com.unity.render-pipelines.universal/ShaderLibrary/Core.hlsl"

            struct Attributes
            {
                float4 positionOS : POSITION;
                float2 uv : TEXCOORD0;
            };
            struct Varyings
            {
                float4 positionHCS : SV_POSITION;
                float2 uv : TEXCOORD0;
            };

            TEXTURE2D(_BaseMap);
            SAMPLER(sampler_BaseMap);
            CBUFFER_START(UnityPerMaterial)
                float4 _BaseMap_ST;
                half4 _BaseColor;
            CBUFFER_END

            Varyings Vert(Attributes input)
            {
                Varyings output;
                output.positionHCS = TransformObjectToHClip(input.positionOS.xyz);
                output.uv = TRANSFORM_TEX(input.uv, _BaseMap);
                return output;
            }
            half4 Frag(Varyings input) : SV_Target
            {
                return SAMPLE_TEXTURE2D(_BaseMap, sampler_BaseMap, input.uv) * _BaseColor;
            }
            ENDHLSL
        }
    }
}

3. Read the structure

PartResponsibility
PropertiesInspector-facing material inputs. Names must match the HLSL declarations.
SubShader / TagsSelect pipeline and rendering category. These tags do not implement lighting.
PassOne rendering pass with its own GPU program and render state.
HLSLPROGRAM / pragmasSelect the named vertex and fragment entry points.
AttributesData from the mesh. POSITION labels a vertex position; TEXCOORD0 labels its first set of texture coordinates.
VaryingsData passed toward the fragment function. Unity blends values such as UVs between the corners. SV_POSITION tells the GPU where the vertex goes on screen before the final screen conversion.
UnityPerMaterialGroups the material’s numbers in a layout Unity can reuse efficiently. Keep the same layout in every pass. Textures and samplers stay outside.
_BaseMap_STTexture tiling in xy and offset in zw; TRANSFORM_TEX applies both.

UVs are addresses on a texture: (0,0) is one corner and (1,1) is the opposite corner. Sampling a texture means asking for its color at a UV address. A fragment is a candidate piece of the image; depth testing can still hide it behind something closer.

HLSL essentials

float is a scalar; float2/3/4 are small vectors. .xyz or .rgb selects components; .xx duplicates one. Vector arithmetic is component-wise: multiplying two colors multiplies each channel. Use mul(matrix, vector) for matrix transformation, not component-wise multiplication.

Use float for positions and UVs that need precision, and half where reduced precision is acceptable, commonly colors. Actual precision depends on the target GPU. saturate(x) clamps to 0–1, lerp(a,b,t) blends without automatically clamping t, and smoothstep(a,b,x) creates a smooth transition. HLSL dot, cross and reflect have the same geometric roles as the Vector3 operations.

4. Experiment with the fragment function

Replace its return line with return half4(input.uv, 0, 1); to see UVs: red increases across U and green across V. Restore texture sampling, then multiply the RGB by 0.75 + 0.25 * sin(_Time.y * 2.0) for a pulse. _Time.y is elapsed time in seconds. This shader is opaque: returning alpha below 1 does not enable transparency.

Going further: Coordinate spaces and lighting

OS is object space; WS is world space; HCS is homogeneous clip space. Use URP's transformation helpers so platform conventions stay correct. A real lit shader needs normals, light data and appropriate lighting calculations. Receiving shadows, casting shadows, depth-only rendering and motion vectors require additional support and passes; this deliberately small shader provides none of those passes.

What happens at runtime

  1. Unity binds the material inputs and mesh attributes.
  2. Vert transforms each vertex and passes texture coordinates onward.
  3. The GPU finds which screen pixels the triangles cover and blends the corner UV values across their surfaces.
  4. Frag samples a texture and returns tinted color; depth testing determines visible fragments.

Common Mistakes

  • Pink material: check Console shader errors, the active pipeline, and include paths.
  • Black texture: confirm assignment and inspect UVs using the gradient test.
  • Using Built-in CGPROGRAM examples or Surface Shaders unchanged in URP.
  • Expecting shader displacement to update mesh bounds or colliders.
  • Adding expensive texture samples or loops without measuring GPU cost on target hardware.
