URP & Post-processing

Set up Unity’s URP graphics system, then add effects such as glow, color changes and darkened screen edges.

Think of filming a scene and then adding a photo filter. URP is the crew that draws the scene. Post-processing is the filter applied to the picture afterward. A Volume Profile is a saved recipe for that filter.

A few words first

URP means Universal Render Pipeline: a system Unity uses to draw your game. Post-processing changes the camera image after the scene is drawn. A Volume tells Unity which effect settings to use, and a Profile stores those settings.

Which asset controls what?

ThingResponsibility
URP Pipeline AssetA saved settings file for how URP draws the game, including shadows and quality.
Renderer DataChooses the drawing steps a camera uses. Use Universal Renderer for this 3D tutorial; 2D Renderer is designed for 2D features.
CameraSelects a renderer, culling, post-processing and Volume settings.
VolumeWhere and how strongly a set of settings applies: global/local, priority and weight.
Volume ProfileSaved effect settings. An override replaces a default setting, such as the default color saturation.

1. Verify URP is actually active

These steps target Unity 6 / URP 17. A Universal 3D template includes the pipeline. For an existing project, install the compatible URP package, create a URP Pipeline Asset with a Universal Renderer, and assign it in Project Settings > Graphics. Check Project Settings > Quality too: a per-quality pipeline override can replace the Graphics default.

Converting a project is more than changing that asset. Convert supported materials with Unity's Render Pipeline Converter and inspect custom shaders separately. Keep conversion changes reviewable in version control. Built-in Standard materials and Surface Shaders do not automatically work in URP; pink usually means an incompatible or failed shader.

2. Create a visible post-processing effect

  1. On the gameplay camera, enable Post Processing in its Rendering settings.
  2. Create a Global Volume and click New beside its Profile. Keep Weight at 1.
  3. Add Color Adjustments. Enable the checkbox next to Saturation and set it to -100 for an obvious grayscale test.
  4. Check the camera's Volume Mask includes the Volume object's layer. This is separate from its geometry Culling Mask.
  5. Restore Saturation to 0, then add Bloom and enable its Intensity override. Use a material with a bright Emission color to test glow. Emission makes the surface look bright; HDR allows brightness values above the usual display range.

A component being present is not enough: its active checkbox and each intended property's override checkbox must be enabled. A Volume's weight blends its contribution. Priority determines the order for overlapping volumes; a higher-priority volume can replace values from a lower-priority one.

Global versus local Volumes

Global affects the camera regardless of distance. For a local effect, untick Is Global and add a collider defining its region; a trigger collider avoids physically blocking the player. Blend Distance softens the transition near the region. URP evaluates local influence using the camera's Volume Trigger transform (normally the camera unless configured otherwise), not every character in the region.

Try a low-priority global neutral profile and a higher-priority local cold-color profile inside a cave. Set a nonzero Blend Distance and walk the camera into it. You do not need an OnTriggerEnter script for this effect. The Volume system checks where the camera is and blends the settings for you.

You can finish a useful setup without writing any code. Save the Profile, enter Play mode, and check that the effect appears. Continue below when you want an effect to respond to gameplay, such as taking damage.

Going further: 3. Control a private runtime profile

Add Vignette to a Volume Profile first. Attach this script to that Volume. Call Flash() from gameplay or its component context menu during Play mode. It clones the profile and its override objects so editing the effect does not change the shared project asset.

using UnityEngine;
using UnityEngine.Rendering;
using UnityEngine.Rendering.Universal;

[RequireComponent(typeof(Volume))]
public class DamageVignette : MonoBehaviour
{
    private Volume volume;
    private VolumeProfile original;
    private VolumeProfile owned;
    private Vignette vignette;
    private float strength;

    void OnEnable()
    {
        volume = GetComponent<Volume>();
        original = volume.sharedProfile;
        owned = ScriptableObject.CreateInstance<VolumeProfile>();
        if (original != null)
            foreach (VolumeComponent component in original.components)
                owned.components.Add(Instantiate(component));
        volume.profile = owned;
        if (!owned.TryGet(out vignette)) vignette = owned.Add<Vignette>(true);
        vignette.active = true;
        vignette.intensity.overrideState = true;
        strength = 0;
    }

    [ContextMenu("Flash")]
    public void Flash() { strength = 0.45f; }

    void Update()
    {
        strength = Mathf.MoveTowards(strength, 0f, Time.unscaledDeltaTime);
        vignette.intensity.value = strength;
    }

    void OnDisable()
    {
        volume.profile = null; // fall back to the unchanged shared profile
        volume.sharedProfile = original;
        if (owned != null)
        {
            foreach (VolumeComponent component in owned.components) Destroy(component);
            Destroy(owned);
        }
        owned = null;
    }
}

This script owns the Volume's runtime profile slot; do not have another script replace it concurrently. The camera still needs to see this Volume, and other higher-priority overrides can affect the final value. The effect fades while paused because it uses unscaledDeltaTime.

Choose effects deliberately

EffectUse and cost
BloomGlow around bright pixels. It does not make an emissive material illuminate nearby geometry.
Tonemapping / Color AdjustmentsFit scene brightness to display and establish a consistent grade. Fix exposure and lighting before compensating with extreme grading.
Depth of FieldFocus cues; needs appropriate depth and can be expensive or blur gameplay targets.
Motion BlurMotion cue; assess comfort and performance, and offer a setting to disable it.
Vignette / Film GrainStylistic image treatment; keep text and important edges legible.

Going further: Cameras, UI and custom effects

Screen Space Overlay UI is rendered after the scene camera and generally bypasses that camera's post-processing. World Space and camera-rendered UI participate differently; verify the actual camera stack and final output. Avoid applying the same treatment twice across cameras.

URP has its own integrated Volume-based post-processing; do not add the Built-in Post Processing Stack v2 workflow. Custom full-screen effects can use a Full Screen Pass Renderer Feature and a suitable material. Advanced ScriptableRendererFeatures in Unity 6 involve Render Graph APIs; old tutorials using legacy render passes may need migration. Depth Texture and Opaque Texture are additional inputs, not universal switches to turn on for every effect.

Performance and troubleshooting

Use the Frame Debugger to see passes and the GPU profiler on target hardware to measure cost. Resolution and render scale affect full-screen effects strongly. Disable effects one at a time to isolate cost. If an effect is missing, check camera Post Processing, active renderer, Volume Mask, profile assignment, weight, component activation, override checkboxes and competing priorities—in that order.

What happens at runtime

  1. The active quality setting selects a pipeline asset.
  2. Each camera uses its renderer to draw the scene.
  3. The Volume system blends applicable overrides.
  4. Enabled effects process the camera image before final presentation.

Common Mistakes

  • Editing one URP asset while the active quality tier uses another.
  • Editing sharedProfile during gameplay and unintentionally changing a shared asset.
  • Assuming a Bloom effect is a physical light.
  • Expecting every Universal Renderer feature to behave identically in the 2D Renderer.
