Procedural Meshes without GameObjects

Make a shape from points and triangles, then draw copies of it without adding a GameObject for every copy.

Imagine cutting a cardboard tile once and using it as a stencil. The mesh is the stencil, the material is the paint, and each matrix says where to stamp a copy. You keep one stencil instead of building a separate model for every tile.

Start here

Build the floor-tile example first. Once you can see the tiles, try changing their spacing. The bounds helper and large-mesh advice are for later.

A few words first

A mesh is a shape made from points joined into triangles. Procedural means your code creates it. A material controls its appearance. Drawing makes it visible; it does not automatically make it solid.

Scope: Unity 6

The example uses one MonoBehaviour as the owner and frame callback. The rendered copies have no GameObjects, MeshRenderers or Transforms. A completely GameObject-free system still needs a lifetime owner and a frame loop, such as a custom PlayerLoop or ECS system.

You will make a square from four points and two triangles. A vertex is one point; vertices is the plural. An index is a point’s number in the list, starting at 0.

What a mesh contains

DataMeaning
VerticesLocal positions; index 0 means the first position.
TrianglesThree vertex indices per triangle. Unity treats clockwise winding, viewed from the front, as front-facing.
UVsTexture coordinates at each vertex; usually 0–1 for a single image.
NormalsSurface directions used for lighting.
TangentsExtra surface directions used by normal-map textures, which fake small bumps. You can skip these for the plain tile.
BoundsAn invisible box around the shape. Unity uses it to decide whether the camera might see the shape.

A vertex index selects a complete set of attributes. Adjacent faces can share indices for smooth normals. At a hard edge or UV seam, duplicate the vertex position so the normals or UVs can differ. A cube often needs 24 vertices, even though it has only 8 corner positions.

Build and draw a floor tile

  1. Create a material using URP/Lit in URP (or Standard in the Built-in pipeline).
  2. Create an empty object and attach ProceduralTiles.cs. Assign the material.
  3. Place a camera above the origin looking down at the XZ plane and add a light. Enter Play mode: there should be a 5 by 5 grid of tiles.
using UnityEngine;
using UnityEngine.Rendering;

public class ProceduralTiles : MonoBehaviour
{
    [SerializeField] private Material material;
    private Mesh mesh;

    void OnEnable()
    {
        mesh = new Mesh { name = "Runtime floor tile" };
        mesh.vertices = new[] {
            new Vector3(-0.5f, 0, -0.5f), new Vector3(-0.5f, 0, 0.5f),
            new Vector3(0.5f, 0, 0.5f), new Vector3(0.5f, 0, -0.5f)
        };
        mesh.uv = new[] { Vector2.zero, Vector2.up, Vector2.one, Vector2.right };
        mesh.triangles = new[] { 0, 1, 2, 0, 2, 3 }; // front faces upward
        mesh.RecalculateNormals();
        mesh.RecalculateBounds();
        // RecalculateTangents() too if the material uses a normal map.
    }

    void Update()
    {
        if (material == null || mesh == null) return;
        var rp = new RenderParams(material) {
            shadowCastingMode = ShadowCastingMode.Off,
            receiveShadows = true
        };
        for (int z = -2; z <= 2; z++)
        for (int x = -2; x <= 2; x++)
        {
            Vector3 position = new Vector3(x * 1.2f, 0, z * 1.2f);
            Matrix4x4 matrix = Matrix4x4.TRS(position, Quaternion.identity, Vector3.one);
            // Valid for these unrotated, unit-scale tiles; give the flat plane thickness.
            rp.worldBounds = new Bounds(position, new Vector3(1, 0.1f, 1));
            Graphics.RenderMesh(rp, mesh, 0, matrix);
        }
    }

    void OnDisable()
    {
        if (mesh != null) Destroy(mesh);
        mesh = null;
    }
}

The owner's Transform intentionally has no effect: the matrices above use world coordinates. For a movable group, multiply each tile matrix by transform.localToWorldMatrix, then update its world bounds too. The assigned material is an asset; the script destroys only the mesh it created.

First experiment: change x * 1.2f and z * 1.2f to use 2 instead. The tiles move farther apart. Their shape stays the same because you changed placement, not vertices.

Going further: Correct bounds for rotated or scaled geometry

Transforming only the minimum and maximum corners is wrong after rotation. Transform the local center and expand each world axis by the absolute contributions of all three local extents. This helper also works when a transform slants the shape, called shear. You do not need it for the unrotated tiles above.

static Bounds TransformBounds(Bounds local, Matrix4x4 m)
{
    Vector3 x = m.MultiplyVector(new Vector3(local.extents.x, 0, 0));
    Vector3 y = m.MultiplyVector(new Vector3(0, local.extents.y, 0));
    Vector3 z = m.MultiplyVector(new Vector3(0, 0, local.extents.z));
    Vector3 e = new Vector3(
        Mathf.Abs(x.x) + Mathf.Abs(y.x) + Mathf.Abs(z.x),
        Mathf.Abs(x.y) + Mathf.Abs(y.y) + Mathf.Abs(z.y),
        Mathf.Abs(x.z) + Mathf.Abs(y.z) + Mathf.Abs(z.z));
    return new Bounds(m.MultiplyPoint3x4(local.center), e * 2f);
}

Changing the mesh

Reuse arrays or lists when updating vertices. Call MarkDynamic once if you will frequently rewrite the mesh. After changing positions, update bounds; update normals and tangents when the surface direction changes. When replacing topology with fewer vertices, clear the mesh before assigning new arrays to avoid stale triangle indices.

The default index format is 16-bit. If you need more than 65,535 vertices, set mesh.indexFormat = IndexFormat.UInt32 before assigning triangles, and check target hardware support. Splitting into chunks gives smaller culling regions and can be better than one huge mesh. UploadMeshData(true) releases CPU-readable mesh data; use it only after all CPU edits and reads are finished.

Rendering is not simulation

These draws do not create collision, navigation, selection, automatic LOD, or per-object events. Store gameplay positions and IDs in your own arrays. Use math queries or a limited set of colliders for interaction. A MeshCollider is a separate component and rebuilding its collision data frequently can be costly.

Going further: Scaling up

This example still submits 25 separate draws. Use RenderMeshInstanced for compatible repeated meshes and materials, or combine unique static geometry into chunks. Respect its instance-count and shader-data limits; removing GameObjects alone does not guarantee fewer draw calls. For large procedural builds, consider MeshData with Jobs/Burst after profiling the simple implementation.

What happens at runtime

  1. OnEnable creates and uploads one mesh.
  2. Update submits that mesh at each matrix for this frame.
  3. Unity culls using the supplied bounds and renders visible submissions later.
  4. OnDisable releases the runtime mesh; no more draws are submitted.

Common Mistakes

  • Calling RenderMesh once and expecting persistence: submit every frame.
  • Wrong winding: the tile disappears from the intended viewing side.
  • Creating a mesh or material per frame: reuse resources and release owned native objects.
  • Changing vertices without expanding bounds: parts disappear near the edge of the screen.
  • Expecting the draw to cast shadows with a shader that has no ShadowCaster pass.
