UI & TextMeshPro in Depth

Build menus, health bars and readable text that still fit when the screen size changes.

Think of a noticeboard. The Canvas is the board, UI elements are the notes pinned to it, and anchors say which part of the board each note should stay near. TextMeshPro prints the words on the notes.

A few words first

UI means user interface: buttons, menus, labels and other things a player reads or uses. A HUD is the information shown during play, such as health or score. TMP is short for TextMeshPro, Unity’s text tool. A RectTransform stores a UI element’s position and size.

Choose a UI system

This guide uses Unity UI (uGUI), where buttons and text are GameObjects inside a Canvas. It is a practical starting point when you already know how to add components in the Inspector. Unity also has UI Toolkit and IMGUI, but their instructions differ. Follow uGUI examples while working through this page.

1. Build a responsive HUD

  1. Create UI > Canvas. Use Screen Space - Overlay for the first HUD.
  2. Set Canvas Scaler to Scale With Screen Size, Reference Resolution 1920×1080, and Match around 0.5 as a starting point. Test your actual aspect ratios; this is not a universal preset.
  3. Create a Panel named SafeArea stretched to all four edges with zero offsets.
  4. Inside it, create a top-left panel anchored and pivoted at (0,1), with a margin such as (24,-24).
  5. Add a Slider for health and a Text - TextMeshPro label. Import TMP Essential Resources if prompted. Disable Slider interaction for a display-only bar.
  6. Use a Horizontal or Vertical Layout Group for related elements, with padding and spacing. Use Layout Elements to specify flexible or preferred sizes.

Anchors, pivot and offsets

Anchors are normalized positions in the parent rectangle. Equal min/max anchors pin an element to a point; different anchors stretch it across an area. The pivot is the element's own origin for position, scale and rotation. Anchored Position is relative to the anchor reference, not a world position. A top-right counter should follow the parent's top-right anchor rather than a hard-coded screen X coordinate.

A layout group owns its children's layout axes. A Content Size Fitter sizes its own RectTransform from content. Do not make a child fitter and a parent layout group fight over the same size. For a scrolling list, a common arrangement is ScrollRect > Viewport (RectMask2D) > Content with a Vertical Layout Group and a vertical preferred-size fitter. Give rows predictable preferred heights, or measure variable rows deliberately.

Change one label first

Create a Text - TextMeshPro object. Attach this script to an empty object, then drag the text object into its Label field. Press Play: it should say “Coins: 10.” Use a public method like this when your game awards coins.

using TMPro;
using UnityEngine;

public class CoinLabel : MonoBehaviour
{
    [SerializeField] private TMP_Text label;

    void Start() { ShowCoins(10); }

    public void ShowCoins(int coins)
    {
        if (label != null) label.SetText("Coins: {0}", coins);
    }
}

{0} is a placeholder: SetText replaces it with the first number you provide. You do not have to update a label every frame if its value has not changed.

An event is a notification. Think of a doorbell: the health script rings it when health changes, and the HUD responds. Subscribing means listening for the bell; unsubscribing means stopping. The two scripts below separate the health rules from the display.

2. Update the health display when health changes

Save these as two separate scripts. Put HealthModel on the player. Put HealthHud on the HUD panel and assign the model, Slider and TMP label. In Play mode use the model's Take 10 Damage context menu: both views should update immediately.

using System;
using UnityEngine;

public class HealthModel : MonoBehaviour
{
    [SerializeField, Min(1)] private int maximum = 100;
    public int Current { get; private set; }
    public int Maximum => maximum;
    public event Action<int, int> Changed;

    void Awake() { maximum = Mathf.Max(1, maximum); Current = maximum; }

    public void Damage(int amount)
    {
        int next = Mathf.Clamp(Current - Mathf.Max(0, amount), 0, maximum);
        if (next == Current) return;
        Current = next;
        Changed?.Invoke(Current, maximum);
    }

    [ContextMenu("Take 10 Damage")]
    private void TestDamage() { Damage(10); }
}

using TMPro;
using UnityEngine;
using UnityEngine.UI;

public class HealthHud : MonoBehaviour
{
    [SerializeField] private HealthModel model;
    [SerializeField] private Slider bar;
    [SerializeField] private TMP_Text label;

    void OnEnable()
    {
        if (model == null || bar == null || label == null) return;
        model.Changed += Refresh;
        Refresh(model.Current, model.Maximum);
    }

    // All scene Awake calls finish before Start: refresh initial model state.
    void Start()
    {
        if (model != null && bar != null && label != null)
            Refresh(model.Current, model.Maximum);
    }

    void OnDisable()
    {
        if (model != null) model.Changed -= Refresh;
    }

    private void Refresh(int current, int maximum)
    {
        bar.SetValueWithoutNotify(current / (float)Mathf.Max(1, maximum));
        label.SetText("Health: {0} / {1}", current, maximum);
    }
}

Set the Slider range to 0–1 and Whole Numbers off. The model owns health; the view only displays it. This avoids reading text back as game state and avoids rebuilding the same text every frame. The example assumes the serialized model reference stays fixed while enabled; if you switch players, unsubscribe from the old model before subscribing to the new one.

TextMeshPro fundamentals

Use TextMeshProUGUI for Canvas text and TextMeshPro for mesh text in the world. Both derive from TMP_Text, making it a useful serialized field type. TMP font assets store glyph and atlas information, not just a reference to a font file. Signed-distance-field rendering helps text stay crisp over a useful scale range, but tiny text still needs readable size and contrast.

  • Fonts and fallbacks: choose a primary font, then explicit fallbacks for missing scripts and symbols. Test real localized strings, accents and numerals. A missing glyph is not fixed by changing text color.
  • Static versus dynamic atlases: a static atlas gives predictable glyph coverage. A dynamic atlas can add glyphs as needed but may incur work and memory growth; plan coverage and test on the target device.
  • Wrapping and overflow: decide whether a label wraps, truncates, uses ellipsis or grows. Reserve enough space for translations and larger accessibility text sizes.
  • Auto Size: use bounded minimum/maximum values for constrained labels. It can involve repeated layout work and make neighboring labels inconsistent; it is not a substitute for a flexible layout.
  • Rich text: useful for authored emphasis. Disable richText for raw player names or chat when markup must not be interpreted.
  • Materials: share font material presets where possible. Per-label material instances and different atlases can split batches.

3. Respect screen safe areas

Attach this to SafeArea, which must be a direct child of a full-screen Overlay Canvas. It maps Screen.safeArea to normalized anchors when dimensions or safe-area values change. This example does not handle camera viewports or multiple displays; those need conversion relative to their own pixel rectangle.

using UnityEngine;

[RequireComponent(typeof(RectTransform))]
public class SafeAreaPanel : MonoBehaviour
{
    private RectTransform panel;
    private Rect previous;
    private Vector2Int previousSize;

    void Awake() { panel = GetComponent<RectTransform>(); }

    void Update()
    {
        if (Screen.width <= 0 || Screen.height <= 0) return;
        Rect safe = Screen.safeArea;
        Vector2Int size = new Vector2Int(Screen.width, Screen.height);
        if (safe == previous && size == previousSize) return;
        previous = safe;
        previousSize = size;
        panel.anchorMin = new Vector2(safe.xMin / size.x, safe.yMin / size.y);
        panel.anchorMax = new Vector2(safe.xMax / size.x, safe.yMax / size.y);
        panel.offsetMin = panel.offsetMax = Vector2.zero;
    }
}

Input and menu focus

Use an EventSystem with the input module matching your project: InputSystemUIInputModule for the new Input System, or StandaloneInputModule for legacy input. Avoid duplicate active EventSystems or competing modules. Keep a GraphicRaycaster on interactive Canvases; turn Raycast Target off on decorative labels and images so they do not intercept clicks.

When opening a modal menu, select a sensible default Button for keyboard/gamepad use and restore the prior selection when closing. Test explicit navigation where automatic navigation picks the wrong neighbor. A CanvasGroup can control visibility and interaction: hiding via alpha alone leaves invisible UI able to block clicks. Set interactable and blocksRaycasts consistently. Disabling gameplay's action map while a menu is open prevents one button press controlling both systems.

Going further: Better performance practices

Changing text, layout or graphics can dirty parts of the Canvas and trigger rebuilds. Split Canvases by update frequency when profiling shows a benefit—for example a mostly static frame versus a changing HUD. Every Canvas also has batching costs; one Canvas per element is not a good default.

Avoid deep nested layout groups in rapidly changing lists. Reuse row objects (pooling) and show only the rows currently visible (virtualization) instead of creating thousands of active entries. Prefer RectMask2D for a rectangular viewport when suitable. Limit transparent full-screen layers because overlapping UI spends GPU time even when most of it is visually redundant. Avoid repeatedly calling ForceUpdateCanvases or ForceMeshUpdate; request immediate layout only when code genuinely needs the freshly computed geometry.

Accessibility and validation

Test 16:9, ultrawide, narrow portrait, a notched device and increased text size. Use meaningful labels, strong contrast and a visible focus state. Do not encode health or rarity using color alone. Make touch targets generous and ensure a controller can reach and leave every modal. Keep long localization strings in the test set, not just short English placeholders.

What happens at runtime

  1. The model changes once and emits a notification.
  2. The HUD updates the numeric label and bar.
  3. Layout and graphics rebuild as needed before Canvas rendering.
  4. The EventSystem routes input to eligible UI graphics and the selected control.

Common Mistakes

  • Reassigning identical text every Update instead of responding to changes.
  • Subscribing on every enable without unsubscribing on disable.
  • Hard-coding screen positions rather than anchors and margins.
  • Scaling down a whole menu until small text becomes unreadable.
  • Using alpha 0 as the only way to hide an interactive panel.
