Working with CharacterController

Make a player walk, jump and slide along walls while you control how the movement feels.

Imagine moving a person inside a clear, capsule-shaped bumper. You tell the bumper where to go, and it stops the person from passing through walls. You still have to tell it when to fall or jump.

A few words first

A CharacterController is a Unity component for moving a character while checking collisions. A capsule is a cylinder with rounded ends. A collider is the invisible shape Unity uses to detect contact.

Choose the movement owner

Your script tells a CharacterController how far to move. The controller checks walls and floors along the way. It does not fall or respond to forces by itself. It is useful when you want to choose exactly how walking and jumping feel. A Rigidbody is useful when physics should control the movement, such as a ball rolling downhill. Do not let a Rigidbody, NavMeshAgent and CharacterController all move the same character.

Set up a test scene

  1. Create a floor and a few boxes with colliders, including a low step and a slope.
  2. Create an empty Player at (0, 1, 0). Add a CharacterController: Height 2, Radius 0.5, Center (0, 0, 0). Put any visual model under it as a child.
  3. Install the Input System package and enable it in Active Input Handling. This example creates and owns its actions in code, so no PlayerInput component is needed.
  4. Create a camera looking at the player, attach the following script to Player, and assign that camera's Transform to View.
  5. Use WASD or the left stick to move; Space or the gamepad south button to jump. Keep the camera outside the player's capsule.

Save the script as SimpleCharacterMotor.cs. The Inspector fields are its controls: Speed is metres per second, Jump Height is metres, and Gravity is negative because it pulls downward. Each frame the script reads input, adds falling speed, and asks the controller to move.

Complete movement example

using UnityEngine;
using UnityEngine.InputSystem;

[RequireComponent(typeof(CharacterController))]
public class SimpleCharacterMotor : MonoBehaviour
{
    [SerializeField] private Transform view;
    [SerializeField] private float speed = 5f;
    [SerializeField] private float jumpHeight = 1.5f;
    [SerializeField] private float gravity = -20f; // must stay negative
    private CharacterController controller;
    private InputAction move;
    private InputAction jump;
    private float verticalSpeed;

    void Awake()
    {
        controller = GetComponent<CharacterController>();
        move = new InputAction("Move", InputActionType.Value);
        move.AddCompositeBinding("2DVector")
            .With("Up", "<Keyboard>/w").With("Down", "<Keyboard>/s")
            .With("Left", "<Keyboard>/a").With("Right", "<Keyboard>/d");
        move.AddBinding("<Gamepad>/leftStick");
        jump = new InputAction("Jump", InputActionType.Button);
        jump.AddBinding("<Keyboard>/space");
        jump.AddBinding("<Gamepad>/buttonSouth");
    }

    void OnEnable() { move.Enable(); jump.Enable(); }
    void OnDisable() { move.Disable(); jump.Disable(); verticalSpeed = 0; }
    void OnDestroy() { move.Dispose(); jump.Dispose(); }

    void Update()
    {
        if (Time.deltaTime <= 0 || !controller.enabled) return;
        Vector2 input = Vector2.ClampMagnitude(move.ReadValue<Vector2>(), 1f);
        Vector3 forward = view != null ? view.forward : Vector3.forward;
        forward.y = 0;
        if (forward.sqrMagnitude < 0.0001f) forward = Vector3.forward;
        forward.Normalize();
        Vector3 right = Vector3.Cross(Vector3.up, forward);
        Vector3 horizontal = (right * input.x + forward * input.y) * speed;

        // isGrounded describes the previous Move, not a fresh probe.
        if (controller.isGrounded && verticalSpeed < 0) verticalSpeed = -2f;
        if (controller.isGrounded && jump.WasPressedThisFrame())
            verticalSpeed = Mathf.Sqrt(jumpHeight * -2f * gravity);
        verticalSpeed += gravity * Time.deltaTime;

        CollisionFlags flags = controller.Move(
            (horizontal + Vector3.up * verticalSpeed) * Time.deltaTime);
        if ((flags & CollisionFlags.Above) != 0 && verticalSpeed > 0)
            verticalSpeed = 0;
        if ((flags & CollisionFlags.Below) != 0 && verticalSpeed < 0)
            verticalSpeed = -2f;
    }
}

Read the movement step

  1. ReadValue gets the stick or keyboard direction.
  2. The camera’s forward and right directions turn that input into movement in the scene.
  3. verticalSpeed remembers how fast the player is rising or falling.
  4. Move tries the combined movement and reports what the capsule hit.

Time.deltaTime is the time since the previous frame. At 5 metres per second, a frame lasting 0.02 seconds should move the player 0.1 metres. That is why the code multiplies speed by deltaTime.

Move versus SimpleMove

Move accepts displacement in metres for this call. A velocity in metres per second must be multiplied by deltaTime exactly once. It does not apply gravity. SimpleMove accepts a velocity, ignores its Y component, and applies gravity itself; it is a convenient walking helper, but not the jump motor used above. Choose one movement path.

The jump formula comes from v² = 2gh. Gravity is negative in this example, so launch speed is sqrt(-2 * gravity * height). Integration is discrete, so the measured peak varies slightly with frame rate and collisions. CollisionFlags can report more than one contact at once: standing against a wall can report both Sides and Below. The & checks in the script test whether a particular contact is present.

Tune the capsule

SettingMeaning and starting point
Height, Radius, CenterFit the collision capsule to the model, not its decorative accessories. Keep the root at unit scale.
Slope LimitMaximum climbable slope angle. Try 45 degrees and test ramps on both sides of that limit.
Step OffsetHow high a step it can climb. Try 0.3 for a roughly two-metre character; it must not exceed capsule height.
Skin WidthTolerance that reduces jitter and sticking. Start around 10% of radius and above 0.01, then test.
Min Move DistanceMovements smaller than this can be ignored. Usually leave at 0 for character movement.

Going further: Grounding and slopes

The small negative grounded speed keeps submitting a downward move, making ground contact more consistent. It is not a full ground-snap system: fast downhill movement and ledges can still leave the ground. For stronger grounding, use a short capsule or sphere cast, reject surfaces steeper than your walkable angle, and snap only while falling and near the ground. Exclude the player's own layers from probes.

For forgiving jumps, record the last grounded time (coyote time) and the last jump-pressed time (input buffering); allow a jump when both windows overlap, then consume the buffered request. Do not repeatedly jump just because the button remains held.

Going further: Moving platforms, pushing and crouching

A controller does not automatically inherit platform motion. Record the contact platform and a local contact point, transform that point next frame, and add its world displacement to your Move. Include rotation around the platform's pivot. Clear the platform reference when jumping or losing contact.

OnControllerColliderHit can identify a Rigidbody to push. Apply a deliberate horizontal force with mass and speed limits; do not drive a dynamic body by writing its Transform. Crouching changes both height and center so the feet remain in place. Before standing, check the expanded capsule for blocking geometry.

What happens at runtime

  1. Read input once in Update and construct horizontal camera-relative velocity.
  2. Update the stored vertical speed for gravity and jumping.
  3. Submit one combined displacement; the controller resolves collisions.
  4. Use flags to cancel velocity into the ceiling or floor.

Common Mistakes

  • Multiplying SimpleMove by deltaTime, or forgetting it for Move.
  • Writing transform.position for ordinary movement and bypassing collision resolution.
  • Reading isGrounded before the first Move and assuming a fresh ground test.
  • Normalizing analog stick input and losing slow movement; clamp its magnitude instead.
  • Assuming slope limit makes the character slide down steep slopes automatically; author that behavior explicitly.

Try it

Test diagonal speed, jumping under a low ceiling, walking down a slope, hitting a wall at an angle, stepping over a box, and pausing at timeScale 0. These reveal different failures; a flat floor alone is not enough.
