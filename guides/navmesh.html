NavMesh in Depth

Teach a character where it can walk, give it a destination, and help it find a way around walls.

A NavMesh is like a map of footpaths. The agent is a person following the map. You choose the destination; Unity finds a route and helps the person walk around nearby people. A map cannot decide whether your enemy should chase the player or go home—that is your game’s rule.

Start here

Bake a floor and try the short walk-to-target script first. Once that works, use the longer example to handle moving targets and places the character cannot reach.

A few words first

A NavMesh is a map of the places a character can walk. Baking means asking Unity to build that map from your level. An agent is a character that follows it. A path is a route from the character to its destination.

Unity 6 with AI Navigation 2.x

Install com.unity.ai.navigation through Package Manager. This guide uses NavMeshSurface and NavMeshLink from the package, not the older Navigation-window-only baking workflow. Agent and query APIs are in UnityEngine.AI; package components such as NavMeshSurface are in Unity.AI.Navigation.

The pieces

PieceJob
NavMeshSurfaceLooks at the floor and walls, then builds a walking map for one kind of character.
NavMeshAgentRequests paths and steers a character along them.
NavMeshObstacleRepresents an obstacle for avoidance and optionally carving.
NavMeshLinkConnects otherwise separated walkable regions, such as a jump or doorway.
NavMeshModifier / ModifierVolumeChanges how geometry or regions contribute to the bake.
Areas and area costsControl which regions an agent may use and which routes it prefers.

1. Bake a small test level

  1. Create a floor and walls with colliders. Leave a doorway and add a separate platform across a gap.
  2. Add NavMeshSurface to a level root. Choose an Agent Type and collect the intended level objects or layers. With Use Geometry set to Physics Colliders, confirm all required floor/wall colliders exist.
  3. In the agent-type bake settings, choose radius, height, maximum slope and step height matching your character. Bake from the Surface Inspector.
  4. Inspect the navigation overlay: the doorway must remain connected; walls and the gap must not be walkable.
  5. Create a character with NavMeshAgent using the same Agent Type. Place its root on the baked surface and adjust the visual child or Base Offset as needed.
  6. Create a target Transform somewhere on the same walkable region. Assign it to the script below and enter Play mode.

During baking, Unity leaves a gap near walls and edges so the character’s body has room to fit. Radius controls the size of that gap. Making an agent's runtime radius smaller does not magically add a doorway removed by the bake. If a large monster should avoid gaps that a small character can use, give them different agent types and bake a map for each. Agent height determines clearance under ceilings; step and slope settings determine which changes in elevation connect.

First, walk to one place

Save this as WalkToTarget.cs and attach it to your character. Drag the target object into Destination. Press Play: the character should walk toward it. If it does not, check that both objects are on connected parts of the baked map.

using UnityEngine;
using UnityEngine.AI;

[RequireComponent(typeof(NavMeshAgent))]
public class WalkToTarget : MonoBehaviour
{
    [SerializeField] private Transform destination;

    void Start()
    {
        NavMeshAgent agent = GetComponent<NavMeshAgent>();
        if (destination == null || !agent.isOnNavMesh) return;
        agent.SetDestination(destination.position);
    }
}

GetComponent finds the agent on this object. isOnNavMesh checks that it is on the walking map. SetDestination asks it to go somewhere. This script asks once in Start; moving the target later will not update the request.

For your next experiment, put the target behind a wall with a doorway. The character should go through the doorway. Then put it in a sealed room: the short script does not explain failure, which is what the longer example below adds. Remove WalkToTarget before adding FollowNavTarget so only one script gives movement orders.

2. Follow a target without requesting a path every frame

This example checks the target a few times per second. It looks for a walkable spot nearby and remembers whether Unity accepted the request. It stops rather than silently continuing toward an old destination when a new request fails. For a large crowd, give different characters different update times so they do not all ask for a route at once.

using UnityEngine;
using UnityEngine.AI;

[RequireComponent(typeof(NavMeshAgent))]
public class FollowNavTarget : MonoBehaviour
{
    [SerializeField] private Transform target;
    [SerializeField, Min(0.05f)] private float repathInterval = 0.25f;
    [SerializeField, Min(0.01f)] private float targetMoveThreshold = 0.5f;
    private NavMeshAgent agent;
    private Vector3 requestedTarget;
    private float nextRequest;
    private bool requested;
    public string Status { get; private set; } = "Idle";

    void Awake() { agent = GetComponent<NavMeshAgent>(); }

    void OnDisable()
    {
        if (agent != null && agent.isActiveAndEnabled && agent.isOnNavMesh)
            agent.ResetPath();
        requested = false;
        nextRequest = 0;
    }

    void Update()
    {
        if (!agent.isActiveAndEnabled || !agent.isOnNavMesh)
        {
            requested = false;
            Status = "Agent is not on a NavMesh";
            return;
        }
        if (target == null)
        {
            if (requested) agent.ResetPath();
            requested = false;
            Status = "No target";
            return;
        }

        if (Time.time >= nextRequest && !agent.pathPending)
        {
            nextRequest = Time.time + Mathf.Max(0.05f, repathInterval);
            bool moved = (target.position - requestedTarget).sqrMagnitude >
                targetMoveThreshold * targetMoveThreshold;
            if (!requested || moved)
            {
                var filter = new NavMeshQueryFilter {
                    agentTypeID = agent.agentTypeID, areaMask = agent.areaMask
                };
                if (!NavMesh.SamplePosition(target.position, out NavMeshHit hit, 1f, filter))
                {
                    agent.ResetPath();
                    requested = false;
                    Status = "No nearby destination";
                    return;
                }
                requested = agent.SetDestination(hit.position);
                requestedTarget = target.position;
                if (!requested)
                {
                    agent.ResetPath();
                    Status = "Request rejected";
                    return;
                }
                Status = "Path requested";
                return; // allow the asynchronous request to progress
            }
        }

        if (!requested) return;
        if (agent.pathPending) { Status = "Calculating"; return; }
        if (agent.pathStatus != NavMeshPathStatus.PathComplete)
        {
            Status = "Destination unreachable";
            agent.ResetPath();
            requested = false; // retry after the rate limit
            return;
        }
        bool close = !float.IsInfinity(agent.remainingDistance) &&
            agent.remainingDistance <= agent.stoppingDistance + 0.05f;
        Status = close && agent.velocity.sqrMagnitude < 0.01f
            ? "Arrived" : "Moving";
    }
}

Request accepted does not mean destination reachable

SetDestination returns whether Unity accepted the request. Path calculation can take later frames. While pathPending is true, do not interpret remainingDistance as a finished result. Once ready, PathComplete reaches the destination, PathPartial reaches only an accessible endpoint, and PathInvalid means no usable route. remainingDistance can be infinity while unknown.

SamplePosition finds nearby NavMesh; it does not test a walkable connection from the agent, or line of sight through walls. In a multi-storey building it can choose another floor. Keep the search radius small, constrain the agent type and area mask, and validate the resulting path. The example's “Arrived” refers to the sampled destination, which may differ from the exact target Transform.

Going further: Movement settings and animation

Speed is a maximum, acceleration controls how quickly the agent reaches it, angularSpeed limits turning, and stoppingDistance defines the arrival region. Enable autoBraking when it should slow near a destination; continuous patrols may need different behavior. Use desiredVelocity to understand steering intent and velocity for actual agent motion.

Choose one position owner. In the simplest setup the agent updates Transform and the Animator only animates a child model. For root motion, disable updatePosition and explicitly synchronize the animated Transform with the agent's nextPosition; otherwise the simulation and model drift apart. A dynamic Rigidbody and an agent updating position will fight. A kinematic Rigidbody can support trigger interaction without becoming another motion solver.

Areas and route preferences

An area mask prohibits travel through excluded areas. Area cost makes allowed travel more expensive, such as mud compared with pavement; it does not enforce a hard prohibition. A longer low-cost route can win over a shorter expensive one. NavMeshModifiers affect the bake, so changing one does not instantly rewrite an existing NavMesh.

Doors and moving obstacles

Avoidance is like stepping around a person in front of you; it does not redraw the route on the map. Carving is like marking a blocked section on the map. It cuts a hole in the walking area so Unity can plan around a stationary obstacle. Moving carving obstacles have update thresholds and timing; enabling carving does not guarantee an immediate rebuilt route in the same frame.

For a door, align collision and navigation state: an open doorway should be both physically passable and navigable. A closed door can use a carving obstacle or a controlled link depending on your layout. Do not enable a carving NavMeshObstacle and a moving NavMeshAgent on the same character at the same time; it may try to avoid its own hole. Test many agents at a narrow doorway; local avoidance does not guarantee that crowds can never deadlock.

Links: jumps, ladders and disconnected platforms

Add a NavMeshLink with endpoints landing on the intended surfaces, the correct agent type, width and directionality. A link adds connectivity; it does not author a jump animation or physics. With automatic traversal enabled, the agent can traverse a supported link itself. For authored traversal, disable autoTraverseOffMeshLink, detect isOnOffMeshLink, take temporary ownership of movement, animate to the endpoint and call CompleteOffMeshLink when finished.

Account for cancellation, object disable and a destination becoming invalid during traversal. ResetPath while on an off-mesh link can complete the link immediately, so a production traversal state should handle stopping deliberately. Teleport using agent.Warp and check its return value after finding a valid location; merely writing transform.position can desynchronize navigation.

Going further: Runtime building and changing levels

NavMeshSurface.BuildNavMesh() builds from the current collected geometry and can cause a noticeable main-thread cost. For updates to an existing surface, UpdateNavMesh(surface.navMeshData) returns an AsyncOperation; schedule and track it instead of rebuilding every frame. Do not start overlapping builds on the same surface. Chunk large worlds, limit collected sources, and wait for new data before sending agents into a region.

Moving a platform is not the same as updating walkable connectivity. Design boarding, travel and disembarking states, keep links/endpoints synchronized, and test the AI Navigation version you ship. A static baked route is not a general solution for elevators and vehicles.

Troubleshooting checklist

SymptomInspect
Agent not on NavMeshSurface baked and enabled; matching agent type; spawn position close to that surface.
No route through a doorBake radius/clearance, disconnected polygons, area mask, closed obstacle or missing link.
Stops shortstoppingDistance, target sampling offset, partial path and collision ownership.
Jitter / snappingTwo movement systems writing the same Transform; animation and nextPosition disagree.
Spikes with crowdsToo many simultaneous path requests, expensive avoidance and excessive runtime rebakes.

What happens at runtime

  1. Your gameplay logic picks a goal.
  2. Unity searches the baked connectivity to build a path.
  3. The agent steers along that path and applies local avoidance.
  4. Your code monitors success, retries or failure and drives animation or interactions.

Common Mistakes

  • Using a collider as proof that an area was baked into navigation.
  • Treating a successful SamplePosition as proof of reachability.
  • Testing only a path to an accessible target: also try another floor and a sealed room.
  • Repathing every Update for a stationary target.
  • Assuming local avoidance replaces level-design clearance or crowd planning.
