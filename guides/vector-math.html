Dot, Cross & Reflect

Learn three useful tools for directions: check what is in front of you, find a surface direction, and make something bounce.

Picture a ball on a pool table. Dot checks how much its travel direction agrees with another arrow. Cross builds an arrow sticking straight out of the table from two directions along it. Reflect changes the ball’s direction when it bounces off a cushion.

A few words first

A vector is a group of numbers that can describe an arrow. Its magnitude is its length. Normalizing makes the length 1 without changing the direction. That gives a unit vector. A zero-length arrow has no direction.

Before the operations: what does the vector mean?

A position is a location. Subtract two positions to get a displacement: target - origin. Its magnitude is distance; its normalized value is direction. A velocity carries direction and speed. Measure both arrows relative to the same thing: do not compare a world direction with a local direction. Check for nearly zero length before calculations that need a direction.

Try pointing both hands forward: those directions agree. Point one forward and the other backward: they disagree. Dot puts a number on that idea.

Dot: a signed amount of alignment

Dot(a,b) = ax*bx + ay*by + az*bz = |a| |b| cos(angle). The answer is a single number, also called a scalar. The bars in |a| mean the length of a. For unit vectors only, it ranges from -1 to 1: +1 is same direction, 0 perpendicular, -1 opposite. Dot((2,0,0),(3,0,0)) = 6, so an arbitrary dot product is not an angle or a percentage.

Field of view without calculating an angle

For a 90-degree total cone, compare against the cosine of 45 degrees. Also check distance. A cone test does not detect walls; add a raycast for line of sight. Attach this script to a guard and assign a target; watch the Scene view while playing.

using UnityEngine;

public class ViewCone : MonoBehaviour
{
    [SerializeField] private Transform target;
    [SerializeField, Range(0, 180)] private float fieldOfView = 90;
    [SerializeField] private float range = 10;

    void Update()
    {
        if (target == null) return;
        Vector3 offset = target.position - transform.position;
        float distanceSquared = offset.sqrMagnitude;
        if (distanceSquared < 0.000001f) return; // no meaningful direction
        float threshold = Mathf.Cos(fieldOfView * 0.5f * Mathf.Deg2Rad);
        bool inCone = distanceSquared <= range * range &&
            Vector3.Dot(transform.forward, offset.normalized) >= threshold;
        Debug.DrawLine(transform.position, target.position,
            inCone ? Color.green : Color.red);
    }
}

For a top-down cone, flatten both the forward vector and target offset onto the ground plane, check for zero length, then normalize them. That intentionally ignores height. If you really need the angle, use Acos(Clamp(dot, -1, 1)) * Rad2Deg; rounding can otherwise put the input outside Acos's domain.

Projection and sliding

With unit normal n, Dot(v,n) is the signed amount of v along n. Multiply it by n to get the normal component; subtract it to keep the tangent component. For a non-unit axis a, projection is a * Dot(v,a) / Dot(a,a), provided a is nonzero.

Vector3 n = hit.normal.normalized; // hit is a RaycastHit
Vector3 normalPart = Vector3.Dot(velocity, n) * n;
Vector3 slide = velocity - normalPart;
// Equivalent: Vector3.ProjectOnPlane(velocity, n)
// To remove only inward movement, preserve outward movement:
Vector3 constrained = velocity - Mathf.Min(Vector3.Dot(velocity, n), 0f) * n;

Perpendicular means meeting at a right angle, like a wall and the floor. Cross finds a direction at right angles to both input arrows. Imagine two edges of a book lying on a table: their cross product points up or down through the book.

Cross: a perpendicular vector

Cross(a,b) has magnitude |a| |b| sin(angle), the area of the parallelogram spanned by a and b. It is zero if the arrows point along the same line, even in opposite directions. Swap the two inputs and the result points the other way. In Unity, Cross(Vector3.right, Vector3.up) is Vector3.forward. Use that concrete axis check when you are unsure of orientation.

Given a forward direction on level ground, Cross(Vector3.up, forward) gives right. Given triangle points A, B, C, Cross(B-A, C-A).normalized gives a face normal for that vertex ordering. If the three points lie on one line or on top of each other, there is no real triangle and no valid normal.

Vector3 edge1 = b - a;
Vector3 edge2 = c - a;
Vector3 areaVector = Vector3.Cross(edge1, edge2);
float triangleArea = areaVector.magnitude * 0.5f;
Vector3 normal = areaVector.sqrMagnitude > 0.000001f
    ? areaVector.normalized : Vector3.up; // explicit fallback for this application

Build a stable orientation

A forward vector alone does not define roll. Add a reference up vector, then use cross products to build perpendicular axes. Choose a different reference when forward nearly aligns with up.

static Quaternion FaceDirection(Vector3 direction)
{
    if (direction.sqrMagnitude < 0.000001f) return Quaternion.identity;
    Vector3 forward = direction.normalized;
    Vector3 referenceUp = Mathf.Abs(Vector3.Dot(forward, Vector3.up)) > 0.99f
        ? Vector3.right : Vector3.up;
    Vector3 right = Vector3.Cross(referenceUp, forward).normalized;
    Vector3 up = Vector3.Cross(forward, right);
    return Quaternion.LookRotation(forward, up);
}

Reflect is the bounce tool. Give it the direction toward a wall and the wall’s normal—an arrow sticking straight out of the wall. It gives you the direction away from the wall after a perfect bounce.

Reflect: reverse the normal component

For a unit surface normal n, r = v - 2 * Dot(v,n) * n. The incoming vector points toward the surface. With v = (3,-4,0) and n = (0,1,0), dot = -4 and the reflected vector is (3,4,0). Its magnitude remains 5. Sliding would give (3,0,0): it removes the normal component instead of reversing it.

Draw a bouncing aim ray

Attach to a camera or aiming object. Add colliders to the scene and inspect the Scene view in Play mode. This demonstrates geometry only; it does not move a projectile or replace physics collision handling.

using UnityEngine;

public class BouncePreview : MonoBehaviour
{
    [SerializeField] private float distance = 30f;
    [SerializeField] private LayerMask surfaces = ~0;

    void Update()
    {
        Vector3 origin = transform.position;
        Vector3 direction = transform.forward;
        float remaining = distance;
        const float skin = 0.01f;
        for (int bounce = 0; bounce < 4 && remaining > 0; bounce++)
        {
            if (!Physics.Raycast(origin, direction, out RaycastHit hit,
                remaining, surfaces, QueryTriggerInteraction.Ignore))
            {
                Debug.DrawRay(origin, direction * remaining, Color.yellow);
                break;
            }
            Debug.DrawLine(origin, hit.point, Color.yellow);
            remaining -= hit.distance + skin;
            direction = Vector3.Reflect(direction, hit.normal).normalized;
            origin = hit.point + hit.normal * skin;
        }
    }
}

For a moving ball use a sphere sweep rather than a point ray, and account for movement left after a hit. Reflection alone adds no friction or energy loss. Multiplying the whole reflected velocity by a damping factor reduces tangent speed too; a restitution model instead adjusts only the inward normal component.

What happens at runtime

  1. Subtract positions to establish a direction.
  2. Dot separates alignment or normal motion; cross constructs perpendicular axes.
  3. Reflect uses the surface normal to reverse incoming normal motion.
  4. Your gameplay code decides what to do with these mathematical results.

Common Mistakes

  • Comparing raw dot products to a cosine without normalizing.
  • Taking the cross product in the wrong order and facing backward.
  • Normalizing a nearly zero cross product and expecting a stable orientation.
  • Reflecting about the contact position instead of the surface normal.
  • Starting a second ray exactly on a surface and hitting it again immediately.
