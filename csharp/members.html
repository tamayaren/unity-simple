Fields, Properties & Modifiers

A field is a variable that belongs to a class. A property looks like a field from the outside but runs code when you read or write it. Modifiers control who can see a member (public, private) and how it behaves (static, const, readonly).

Access modifiers

ModifierWho can use it
privateOnly code inside this class. The default if you write nothing.
protectedThis class and classes that inherit from it.
internalAny code in the same assembly (for most Unity projects, all your scripts).
publicAnyone.

Rooms in a house. private is your bedroom: only you go in. protected is the family room: you and your children. internal is the whole house: anyone who lives there. public is the front yard: anyone passing by.

Unity adds a twist: whether a field shows in the Inspector is separate from who can access it in code. public fields and [SerializeField] private fields show up; plain private ones don't. See Better Ways to Do Things.

Properties

A property has a get (runs when read) and/or a set (runs when assigned; the new value is called value).

public class Health : MonoBehaviour
{
    [SerializeField] private float max = 100f;
    private float current;

    // Read-only from outside: others can see it but not change it.
    public float Current => current;          // "=>" is short for a get that returns this

    // Computed property: no stored value, calculated each time.
    public float Percent => current / max;
    public bool IsDead => current <= 0f;

    // Full property with validation.
    public float Max
    {
        get { return max; }
        set
        {
            max = Mathf.Max(1f, value);     // never allow 0 or negative
            current = Mathf.Min(current, max);
        }
    }

    // Auto-property: C# creates the hidden field for you.
    public int Deaths { get; private set; } // anyone can read, only this class can write
}

// Using it: looks just like fields
if (health.IsDead) Respawn();
healthBar.fillAmount = health.Percent;
health.Max = 150f;       // runs the set code
// health.Deaths = 0;    // error: the setter is private

A field is an open box: anyone can reach in and swap what's inside. A property is a box with a shop assistant in front. When you ask for the contents, the assistant can check, calculate or refuse. From the outside, you just "ask the box".

Properties don't show in the InspectorUnity only serializes fields. To show an auto-property, target its hidden field: [field: SerializeField] public int Deaths { get; private set; } .

static

A static member belongs to the class itself, not to any one object. There's only one copy, shared by everything.

public class Enemy : MonoBehaviour
{
    public static int AliveCount;       // one number shared by ALL enemies

    void OnEnable()  { AliveCount++; }
    void OnDisable() { AliveCount--; }
}

// Read it without any enemy reference:
if (Enemy.AliveCount == 0) OpenExitDoor();

You've used static members already: Time.deltaTime, Mathf.Clamp, Vector3.zero, Debug.Log. A static class can only contain static members and can't be instantiated; it's used for helpers like Mathf.

Static fields survive scene loadsA static field keeps its value when you load a new scene (and, in the Editor, can even keep it between Play sessions if "Enter Play Mode Options" disables domain reload). Reset static state yourself when a level starts. Static fields also don't show in the Inspector.

What happens at runtime

  1. Each object gets its own copy of every non-static field. 100 enemies = 100 current health values.
  2. Static fields exist once, created the first time the class is used, and live until the app (or the Editor's script domain) reloads.
  3. A property is really a pair of hidden methods (get_Current(), set_Max(value)). Simple ones are usually inlined, so they cost about the same as a field.
  4. const values are pasted directly into the code where they're used at compile time.

Common Mistakes

  • Making everything public "so it works". Now any script can break your object's state. Default to private; open up only what's needed.
  • Using static to share data between objects that aren't really global. Two players in local multiplayer would share one "static health". Use references instead.
  • A property that calls itself: public float Speed { get { return Speed; } } causes a StackOverflowException. Return the backing field (speed), not the property (Speed).
